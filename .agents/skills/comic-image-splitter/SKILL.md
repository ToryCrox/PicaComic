# 漫画长图切割

当用户要求切割漫画长图、保留原图格式并重排页码时使用本 skill。不要把任何一次任务的目录保存为默认值。

## 操作规则

- 每次都要求明确的输入目录；运行脚本时必须传入 `--input-dir`。用户在当前请求中已给出父目录并明确要求处理子目录时，不要重复询问每个章节目录。
- 默认只处理输入目录顶层。用户明确要求“所有章节”“所有子目录”或递归处理时，逐个处理其下包含漫画图片的章节目录；每章独立编号，不要把不同章节图片展平到同一个目录。遍历时跳过名为 `back` 的备份目录、临时目录和隐藏目录，避免把历史原图或旧切片再次当作新章节处理。
- 所有备份统一放在 Windows 系统“下载”目录下的 `PicaComic Image Splitter Backups` 中，不能在漫画章节源目录创建 `back/`。脚本默认路径按“漫画目录名+漫画目录绝对路径哈希 / 章节目录名+章节绝对路径哈希 / back”生成；递归批处理或临时目录处理时，必须根据原章节路径计算并显式传入 `--backup-dir`，不能根据临时目录路径推算。保留原章节相对层级，不同漫画或同名章节不能互相覆盖。
- 对已切割过的目录再次处理时，不能把当前顶层切片当作原图重切。先从该章节在系统下载目录中的对应 `back/` 识别直接存放的源图备份；只在来源明确且每章唯一时使用。诸如 `*_before_repair`、`*_before_resplit` 的旧切片备份不能作为原始输入；若唯一原图备份缺失或为空，立即停止该章并报告，不能从旧切片猜测拼回原图后继续。将选定原图复制到临时输入目录，逐文件核对清单、字节数和 SHA-256 后再预览、生成结果。保留现有顶层结果时，直接移入该章节对应的下载目录 `back/` 并在文件名加 `_before_resplit`；遇到重名时在文件名加序号，禁止覆盖。原图与旧切片都放在外部 `back/` 直接层级，不建立时间戳子目录。原始备份不得覆盖或删除。调用脚本处理临时目录时，`SourceImage.path` 必须全部是该输入目录的直接子文件；禁止把其他目录的原图对象传给临时目录的 `apply_plans`。
- 脚本默认处理目录顶层、数字文件名的 `.jpg`、`.jpeg`、`.png` 和 `.webp` 图片。遇到非数字图片名、重复数字编号、格式与扩展名不符或动画图片时应停止并报告，不能静默跳过漫画页。
- 默认跳过纯白页：将图片按实际显示效果合成到白色背景后，只有每个像素均为纯白 `(255, 255, 255)` 才判定为空白页。预览需列出被跳过的文件名；执行时仍将原图备份到该章节在系统下载目录的 `back/`，再把源文件移入回收站，不生成该页切片，并让剩余页号连续。带有任何文字、图案、边框或非纯白像素的近白页都保留。用户明确要求保留纯白页时传入 `--keep-blank-pages`。
- 只缩短上下边缘连续的大块近白区域，以及图片宽度方向几乎全白的过宽横向留白；左右边缘绝不裁切，非白背景和普通内部留白保持原样。压缩大横向留白时保留 `10%` 图片宽度的间距（限制在 48–160 px），检测时为画格内容保留安全边距。按处理后的高度规划分段；参考宽度为 2160 px，默认等效高度范围为 3000–5000 px。等效高度按 `图片高度 × 2160 ÷ 图片宽度` 计算；不缩放图片。
- 超限图片按目标平均等效高度约 4000 px 选择段数，优先搜索完整横向留白，再选择低墨量行；切口避开识别到的文字字形区域。若切口无法满足段长限制，会将搜索范围扩展到所有可行位置，并对高墨量行增加代价。仅在候选无法组成可行计划时才回退到均分点。目标下限与上限可通过 `--min-equivalent-height` 和 `--max-equivalent-height` 设置。若原图本身太短，数学上无法让每段同时满足上下限，则优先保证不超过上限，并在预览中提示。预览必须显示实际选中的切口坐标和“留白/低墨量/均分”来源，执行时使用同一份计划。
- 每张源图按输入数字顺序分配页号，默认从 1 开始；每张源图的分段序号从 0 开始。文件名为 `页号-分段号`，例如 `1-0.jpg`、`1-1.jpg`、`2-0.jpg`。即使只输出一页，也使用 `页号-0`。阅读器必须使用自然数字顺序，并让按页索引取图与阅读页列表一致。未切割且未裁边的图片逐字节复制；需要裁边或切割的图片沿用原格式重新编码，不做格式转换。PNG 保持原有色彩模式与透明通道，并以无损方式保存。
- 默认只预览，不修改文件。用户明确要求执行后才添加 `--apply`。执行时先在输入目录同级暂存所有结果并验证可读性、尺寸、格式和编号；全部通过后，先把原图复制到系统下载目录对应的外部 `back/`，逐张校验文件大小与 SHA-256，再放入新结果。若同名外部备份已存在，只能在哈希完全一致时复用；内容不同必须停止，不能覆盖。新结果全部落盘后，才把输入目录中的数字原图移入系统回收站。失败时尽量恢复原图和回滚新结果；外部原图备份始终保留。批量递归处理应逐章隔离暂存和提交：只允许清理本次新建且路径已核验的暂存目录；不得将外部原图移入暂存目录，也不得用永久删除清理含原图或备份的目录。临时文件、失败的部分结果和空暂存目录都先移入系统回收站；若无法使用回收站，就保留原路径并报告，不得回退为 `unlink`、`rmdir` 或递归强制删除。清理暂存前再次核对下载目录原始备份清单的 SHA-256 与执行前一致，并确认临时目录中无原图或唯一备份。
- 优先在完整横向白色留白处分割，可减少切口穿过画格或人物的概率；这只保证源图切点更合适，不保证阅读器把独立图片无缝合成一张图。阅读器可能因缩放、滚动位置和物理像素对齐显示一像素细缝。不要通过擅自重编码白边、加重叠或修改漫画内容来掩盖这种显示缝。
- 依赖 Python、OpenCV、Pillow 和 NumPy。缺依赖时说明缺少项，不要自动安装。

## 使用

先预览本次明确指定的目录：

```powershell
python .agents/skills/comic-image-splitter/scripts/split_comic_images.py --input-dir "<用户提供的目录>"
```

用户要求实际处理时，使用相同的显式目录并添加 `--apply`：

```powershell
python .agents/skills/comic-image-splitter/scripts/split_comic_images.py --input-dir "<用户提供的目录>" --apply
```

脚本默认在系统下载目录计算备份路径；只有递归批处理、临时输入目录或用户指定路径时才显式增加 `--backup-dir "<该原章节在下载目录中的 back 路径>"`。若用户明确要求保留纯白页，增加 `--keep-blank-pages`。用户指定其他切割参数时，可通过 `--reference-width`、`--min-equivalent-height`、`--max-equivalent-height` 和 `--start-index` 覆盖默认值。用户要求递归处理时，逐章运行上述预览和执行流程；全部章节预览通过后再批量执行。处理完成后报告章节数、各章切割数量、纯白页跳过数、输出总数、编号范围和系统下载目录中的备份路径。
