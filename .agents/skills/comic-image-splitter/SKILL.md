# 漫画长图切割

当用户要求切割漫画长图、保留原图格式并重排页码时使用本 skill。不要把任何一次任务的目录保存为默认值。

## 操作规则

- 每次都要求明确的输入目录；运行脚本时必须传入 `--input-dir`。用户在当前请求中已给出父目录并明确要求处理子目录时，不要重复询问每个章节目录。
- 默认只处理输入目录顶层。用户明确要求“所有章节”“所有子目录”或递归处理时添加 `--recursive`，脚本自动遍历，含图片的父目录也作为独立章节处理；每章独立编号，不展平章节。跳过 `back`、系统备份目录、`tmp`/`temp`、脚本暂存目录、隐藏目录及目录链接（含 Windows 目录联接）；输入根目录也不能是目录链接。
- 默认备份统一放在系统“下载”目录的 `PicaComic Image Splitter Backups` 中，不能在输入目录树中创建备份。路径按“章节父目录名+父目录绝对路径哈希 / 章节名+章节绝对路径哈希 / back”自动计算，不同漫画或同名章节不覆盖。递归时无需由 AI 逐章计算路径。用户指定 `--backup-dir` 时，单章将其作为备份目录，递归将其作为备份根目录，再追加“输入根目录名+路径哈希 / 章节相对路径 / back”。重切默认使用章节记录中的原备份路径，不能因临时输入目录改变它。
- 宽度筛选用 `--max-width N`，只处理宽度 **≤N px** 的图片，包含边界；`--max-width 2160` 与计算等效高度的 `--reference-width 2160` 是两个独立参数。排除 WebP 用 `--exclude-webp`，扩展名匹配不区分大小写。不满足条件的图片不裁切、不重编码、不重命名、不备份或移入回收站；预览列出文件名和跳过原因，全部被排除时该章不写入任何内容。
- 再次处理使用 `--resplit`，不能直接重切旧切片。脚本用章节中的 `.comic-image-splitter.json` 记录原图名称、字节数、SHA-256、对应输出和备份路径；筛选时只替换选中原图对应的旧结果，未选中的原图或切片保持原样，也可同时处理章节内尚未切割的数字原图。原图备份及记录中的旧切片缺失、哈希变化、额外切片来源不明或页号冲突时停止该章。递归批次中未处理过的章节仍正常处理。
- 旧版章节没有对应记录时，仅在顶层全部为切片、备份直接层级有唯一数字原图清单、本次筛选没有排除任何原图，且原页数量、格式与切片分组对应、分段序号连续时允许整章重切；局部重切或混合目录无法确认对应关系，必须停止并报告。全部被筛掉时保持该章原样。`*_before_repair`、`*_before_resplit` 永远不能当作原图，不从旧切片猜测拼回原图。
- 重切先从已校验备份生成只读预览；执行时将选定原图复制到本次独立临时输入目录，逐张核对字节数与 SHA-256，再使用同一计划生成和验证新结果。新结果通过后，将旧切片复制到原外部 `back/`，校验后移入回收站；归档名添加 `_before_resplit`，重名追加序号，不覆盖。再放入新结果并更新记录。原图与旧切片归档均在外部 `back/` 直接层级，原始备份不覆盖、不删除。传入 `apply_plans` 的原图必须全部是输入目录的直接子文件，禁止直接传入外部原图对象。
- 脚本默认处理目录顶层、数字文件名的 `.jpg`、`.jpeg`、`.png` 和 `.webp` 图片。遇到非数字图片名、重复数字编号、格式与扩展名不符或动画图片时应停止并报告，不能静默跳过漫画页。
- 默认跳过纯白页：将图片按实际显示效果合成到白色背景（包括 PNG 的调色板透明信息）后，只有每个像素均为纯白 `(255, 255, 255)` 才判定为空白页。预览列出被跳过的文件名；执行时仍备份原图再将源文件移入回收站，不生成切片。全章连续编号模式让剩余页号连续；筛选模式保持原始页号，不压缩空缺。带有任何文字、图案、边框或非纯白像素的近白页都保留。用户要求保留纯白页时传入 `--keep-blank-pages`。
- 只缩短上下边缘连续的大块近白区域，以及图片宽度方向几乎全白的过宽横向留白；左右边缘绝不裁切，非白背景和普通内部留白保持原样。压缩大横向留白时保留 `10%` 图片宽度的间距（限制在 48–160 px），检测时为画格内容保留安全边距。按处理后的高度规划分段；参考宽度为 2160 px，默认等效高度范围为 3000–5000 px。等效高度按 `图片高度 × 2160 ÷ 图片宽度` 计算；不缩放图片。
- 超限图片按目标平均等效高度约 4000 px 选择段数，优先搜索完整横向留白，再选择低墨量行；切口避开识别到的文字字形区域。若切口无法满足段长限制，会将搜索范围扩展到所有可行位置，并对高墨量行增加代价。仅在候选无法组成可行计划时才回退到均分点。目标下限与上限可通过 `--min-equivalent-height` 和 `--max-equivalent-height` 设置。若原图本身太短，数学上无法让每段同时满足上下限，则优先保证不超过上限，并在预览中提示。预览必须显示实际选中的切口坐标和“留白/低墨量/均分”来源，执行时使用同一份计划。
- 不筛选时按输入数字顺序分配连续页号，默认从 1 开始；指定宽度筛选或排除 WebP 时保留原始数字页号，如 `3.jpg` → `3-0.jpg`、`3-1.jpg`，避免与未处理页混序。局部重切也保留原始页号，发现与保留页冲突就停止。这些模式不能同时指定其他 `--start-index`。分段序号从 0 开始，单页也使用 `页号-0`。项目阅读器已有 `sortedByName()` 自然数字排序和按阅读页序取图，无需修改阅读器。未切割且未裁边的图片逐字节复制；需要裁边或切割的图片沿用原格式重新编码。PNG 保持原有色彩模式与透明通道并无损保存。
- 默认只预览，不修改文件。用户明确要求执行后才添加 `--apply`。先预览全部章节，任一章无法确认来源或存在冲突时整批不写入。执行逐章隔离暂存和提交：验证切片可读性、尺寸、格式和编号后，复制并校验原图备份，再放入新结果；新结果全部落盘后才将数字原图移入回收站，最后更新章节记录。同名原图备份仅在哈希一致时复用，不同内容必须停止。失败时尽量恢复原图、旧切片并回滚新结果，已完成章节不回滚，后续章节停止；外部备份始终保留。只清理本次新建且路径已核验的暂存路径，清理前再次核对其原图或备份哈希，不能含唯一原图。临时文件、失败结果和暂存目录使用回收站；失败时保留原路径并报告，不回退为永久删除。
- 优先在完整横向白色留白处分割，可减少切口穿过画格或人物的概率；这只保证源图切点更合适，不保证阅读器把独立图片无缝合成一张图。阅读器可能因缩放、滚动位置和物理像素对齐显示一像素细缝。不要通过擅自重编码白边、加重叠或修改漫画内容来掩盖这种显示缝。
- 依赖 Python、OpenCV、Pillow 和 NumPy；非 Windows 执行还需要 `send2trash`。缺依赖时说明缺少项，不自动安装。

## 使用

先预览本次明确指定的目录：

```powershell
python .agents/skills/comic-image-splitter/scripts/split_comic_images.py --input-dir "<用户提供的目录>"
```

用户要求实际处理时，使用相同的显式目录并添加 `--apply`：

```powershell
python .agents/skills/comic-image-splitter/scripts/split_comic_images.py --input-dir "<用户提供的目录>" --apply
```

递归预览父目录，只处理宽度不超过 2160 的非 WebP 图片：

```powershell
python .agents/skills/comic-image-splitter/scripts/split_comic_images.py --input-dir "<用户提供的父目录>" --recursive --max-width 2160 --exclude-webp
```

用户要求执行时在同一命令末尾添加 `--apply`；要求从原图重新处理时再加 `--resplit`。不指定 `--apply` 的重切也仅预览，保留旧结果原样。递归时脚本自动生成每章备份路径，不需要逐章调用。

要求保留纯白页增加 `--keep-blank-pages`；等效高度参数用 `--reference-width`、`--min-equivalent-height` 和 `--max-equivalent-height`。只有不筛选且不做局部重切时才能用 `--start-index` 修改连续编号起点。

处理完成后报告章节数、各章切割数量、筛选跳过及纯白页跳过数量、输出总数、编号范围和外部备份路径。验证脚本的回归测试位于 `test/skills/comic_image_splitter_test.py`，使用临时合成图片及隔离回收站替身，不处理用户漫画目录。
